# Work Log — 일일 업무 기록 & 주간 보고 도우미 설계

- 작성일: 2026-11-02
- 상태: 검토 반영 완료 (사용자 승인 대기)

## 1. 의도와 배경

매주 주간 보고를 써야 하고, 가끔 "4월부터 위시드콘에 공수 얼마나 들었는지 알려달라"는 요청(원가분석)이 온다. 지금은 매번 기억과 흩어진 메모로 재구성한다.

이 도구는 **매일 1분 안에 "오늘 무엇에 얼마나 썼는지 + 메모"를 남기고**, 그 기록에서

1. 주간 보고 초안을 자동 생성해 복사하고,
2. 항목/서비스별 월별 투입 공수(MD)를 바로 뽑아 답할 수 있게 한다.

동시에 **풀스택 포트폴리오 프로젝트**다. 돌아가기만 하는 게 아니라 구조·테스트·기술 선택을 설명할 수 있어야 한다.

현재 사용자는 본인 1명(개발1팀). 언젠가 팀원도 쓸 수 있도록 데이터 구조는 사용자/팀 단위로 설계한다.

## 2. 목표 / 비목표 / 안티목표

### 목표
- 진행 중인 업무 항목 등록, 상태(대기·진행 중·완료) 관리. 완료하면 일일 목록에서 사라지되 기록은 남음.
- 일일 체크인: 항목별 비중 0·1·2·3 선택 → 그날 근무 MD를 비중대로 자동 분배. 항목별 메모.
- 연차/반차를 미리 등록 → 그날 근무 MD에 반영.
- 주간 탭: "해야 할 일 / 실제 달성한 일 / 차주 업무" 초안 자동 생성 + 원클릭 복사.
- 월별 탭: 항목·서비스 태그 단위, 기간 지정 월별 MD 조회 + 복사.

### 비목표 (이번 범위 아님)
- 팀 기능(팀원 초대, 팀장 열람, 승인) — 스키마만 대비.
- M/M 환산 — 사용자도 회사 기준을 모름. MD로만 계산. (나중에 "1 M/M = N일" 설정 추가 여지만 남김)
- 회사 시스템 연동, 알림, 네이티브 모바일 앱.
- 공휴일 자동 반영(외부 API) — 수동 등록으로 대체.
- 클라우드 배포 — v1은 Docker Compose 로컬 실행까지. 배포는 후속 작업.

### 안티목표 (기술적으로 돌아가도 실패)
- 컬러풀하거나 장식적인 UI. **업무 도구 느낌**이어야 한다.
- 시간을 분/시간 단위로 정밀 입력하게 만드는 것. 입력은 0~3 비중 선택이 전부.
- 항목을 완료/삭제했을 때 과거 공수 기록이 사라지거나 집계에서 빠지는 것.
- 주간 보고 양식을 앱이 강제하는 것. 앱은 **붙여넣기 좋은 초안**까지만 만든다.

## 4. 핵심 개념과 규칙

### 4.1 업무 항목 (WorkItem)
- 필드: 제목, 서비스/고객사 태그(선택, 예: "위시드콘"), 상태, 상시 여부, 정렬 순서, 생성일·시작일·완료일.
- 계층 없음. **항목 하나 = 한 줄.** 세부 내용은 메모로 처리 (사용자 결정).
- 태그는 단순 문자열 라벨. 월별 조회에서 같은 태그 항목을 합산하는 용도. 입력 시 기존 태그 자동완성.
- 상태: `대기(WAITING) → 진행 중(IN_PROGRESS) → 완료(DONE)`. 완료 → 진행 중 되돌리기 허용.
- 상시 항목(유지보수, 회의, 기타 등)은 사실상 계속 진행 중. "상시" 표시만 다르고 규칙은 동일.
- 신규 사용자에게 기본 상시 항목 "회의", "기타"를 만들어 둔다.
- 항목별 옵션 **"계획 섹션에 표시"**(기본 켜짐). 꺼진 항목은 주간 보고의 해야 할 일·차주 업무에 나오지 않고 실제 달성한 일에만 나온다. 기본 항목 "회의", "기타"는 꺼진 상태로 생성 (사용자 결정). "CRM 유지보수" 같은 상시 업무는 켜짐 → 계속 계획 섹션에 표시.
- 일일 체크인 목록에는 **진행 중** 항목만 보인다. 대기 항목은 "대기 항목 보기"로 펼쳐서 비중을 줄 수 있고, 비중 > 0으로 저장하면 자동으로 진행 중으로 바뀐다(시작일 기록).
- 완료 시 완료일 기록. 완료 항목은 일일 목록에서 사라짐. 단, **완료일 이전 날짜를 열면** 그날 기록이 있던 항목은 그대로 보이고 수정 가능.
- 삭제는 기록이 하나도 없는 항목만 가능. 기록이 있으면 완료 처리만 가능.

### 4.2 하루 (DayLog)와 근무 MD
- 날짜별 1건. 근무 형태: `근무(1.0MD)`, `오전 반차(0.5)`, `오후 반차(0.5)`, `연차(0)`, `휴일(0)`.
- 연차/반차/휴일은 미래 날짜에도 미리 등록 가능 (업무 탭 또는 일일 화면 날짜 메뉴).
- 연차·휴일인 날은 비중 입력이 잠긴다.

### 4.3 체크인과 MD 분배
- 그날 각 항목에 비중 0~3과 메모(선택)를 입력. 하루 메모 1개(선택)도 별도로 있음.
- **항목 MD = 그날 근무 MD × (항목 비중 / 그날 비중 합)**.
  - 예: 근무 1.0MD, VOC 2 + 회의 1 → VOC 0.67, 회의 0.33.
  - 예: 오전 반차(0.5MD), VOC 1 → VOC 0.50.
- 비중 합이 0이면 그날은 "기록 없음"(MD 0). 경고만 표시하고 저장 허용(메모만 남기는 경우).
- MD는 저장 시점에 계산해 항목별로 **소수 2자리**로 저장. 반올림 오차는 최대 나머지 방식으로 보정해 **그날 합계가 정확히 근무 MD**가 되게 한다. (원가분석 합계가 어긋나지 않도록)
- 화면에는 MD와 환산 시간(MD × 8h)을 함께 보여준다. 예: `0.67MD · 5.3h`.
- 지난 날짜도 언제든 수정 가능. 수정 시 그날 MD 재계산.
- 저장 버튼 방식(참고 화면과 동일). 저장 전 "오늘 투입 공수" 패널에서 분배 결과 미리보기.

### 4.4 주 (Week)
- 주 = 월~금. 주말 기록은 v1에서 다루지 않는다.
- 보고 제목: `YYYY-MM-DD ~ YYYY-MM-DD {팀명}` (월요일 ~ 금요일). 예: `2026-10-26 ~ 2026-10-30 개발1팀`.
- 팀명은 사용자 설정값(기본 "개발1팀").

## 5. 화면

공통 레이아웃: 상단 반투명 바(앱 이름 + 세그먼트 탭 `일일 / 주간 / 월별 / 업무`). 반투명은 이 조작 영역에만, 내용은 흰 카드. 데스크톱 우선이지만 모바일 폭(375px)에서도 깨지지 않게.

시안: `.superpowers/brainstorm/1187-1793609069/content/daily-v2.html`의 **A안**이 확정된 방향.

### 5.1 일일 (체크인)
- 주 이동(이전/다음/이번 주), 월~금 요일 칩(기록 있는 날 점 표시, 연차·반차 라벨).
- 선택한 날의 제목(예: "11월 2일 월요일")과 근무 형태.
- 진행 중 항목 리스트: 항목명, 상태/상시 라벨, 0·1·2·3 세그먼트, 그 아래 메모 입력(접혔다 펼침).
- "대기 항목 보기" 펼침.
- 하루 메모.
- "오늘 투입 공수" 패널: 항목별 MD·시간 막대, 합계.
- 하단 고정 저장 버튼 `{M월 D일} 체크인 저장`.

### 5.2 주간 (보고 초안)
세 섹션을 카드로 보여주고, 섹션별 복사 + 전체 복사 버튼.

- 해야 할 일·차주 업무는 "계획 섹션에 표시"가 켜진 항목만 대상(4.1).
- **해야 할 일**: 그 주 월요일 시점에 완료되지 않았고 금요일까지 생성된 항목(대기·진행 중). 즉 지난주 "차주 업무" + 이번 주 새로 등록한 항목.
- **실제 달성한 일**: 그 주에 MD > 0 기록이 있는 항목. 항목별로 기록한 요일, 주간 MD 합계, 요일별 메모. 그 주에 완료된 항목은 `(완료)` 표시. 연차/반차가 있으면 별도 줄.
- **차주 업무**: 그 주 금요일 시점에 완료되지 않은 항목(대기·진행 중).
- 과거 주를 열어도 당시 기준으로 재구성된다(시작일·완료일로 판정).

복사 텍스트 예시 (plain text, 붙여넣기 용도. 정확한 문구는 빌더 재량):

```
2026-10-26 ~ 2026-10-30 개발1팀

[해야 할 일]
- 위시드 VOC 홈페이지
- 위시드콘 ADS AI 질의 메뉴
- 위시드 CRM 서비스 유지보수

[실제 달성한 일]
- 위시드 VOC 홈페이지 (월·화·수 / 1.50MD)
  · 월: 회원가입, 휴대전화인증
  · 수: VOC 작성하기 완료
- 위시드콘 ADS AI 질의 메뉴 (완료) (목·금 / 1.20MD)
  · 목: AI 질의 메뉴 진행
- 회의 (월~금 / 0.80MD)
- 10/30(금) 오후 반차

[차주 업무]
- 위시드 VOC 홈페이지
- 위시드 CRM 서비스 유지보수
```

### 5.3 월별 (공수 조회)
실제로 오는 요청: *"4월부터 위시드콘만 공수 얼마나 투입됐는지, 예) 5월 0.5, 6월 1.0"*. 이걸 첫 화면으로.

- **공수 조회(기본 뷰)**: 대상 선택(태그 또는 개별 항목, 완료 항목 포함) + 시작 월 ~ 종료 월 → 월별 MD 목록 + 합계 + 복사.
  ```
  위시드콘 투입 공수 (2026-04 ~ 2026-10)
  4월 3.50MD
  5월 10.25MD
  ...
  합계 42.00MD
  ```
- **월간 요약 뷰**: 월 선택 → 항목별 그 달 MD 표(태그, 항목, MD, 비율), 근무일 수, 연차/반차 사용, 총 MD. 표 복사(탭 구분, 엑셀 붙여넣기용).

### 5.4 업무 (항목 관리)
- 진행 중 / 대기 / 완료(접힘) 그룹 목록. 각 항목: 제목, 태그, 상시 여부, 누적 MD, 시작·완료일.
- 등록·수정·상태 변경·정렬(드래그 또는 위/아래).
- 연차·반차·휴일 등록 목록(날짜 + 종류)도 이 탭 하단에.
- 설정: 팀명.

## 7. 데이터 모델 (초안)

```
teams        (id, name)
users        (id, email unique, password_hash, name, team_id → teams null, team_label default '개발1팀', created_at)
work_items   (id, user_id, title, tag null, status WAITING|IN_PROGRESS|DONE, recurring bool, show_in_plan bool default true,
              sort_order, created_at, started_at null, completed_at null)
day_logs     (id, user_id, date, day_type WORK|HALF_AM|HALF_PM|ANNUAL|HOLIDAY, work_md numeric(3,2),
              memo text null, unique(user_id, date))
day_entries  (id, day_log_id, work_item_id, weight smallint 0..3, md numeric(4,2), memo text null,
              unique(day_log_id, work_item_id))
```

- 모든 조회는 `user_id`로 범위 제한(팀 확장 대비).
- 시작일·완료일은 날짜 단위 판정에 쓰인다(주간 보고 재구성). 사용자가 직접 수정할 수 있게 한다(소급 기록 대비).
- 월별 집계는 `day_entries.md` 합산 SQL.

## 8. API (윤곽, 세부는 빌더 재량)

- `POST /api/auth/login`, `POST /api/auth/signup`(설정으로 끌 수 있게), `GET /api/me`, `PATCH /api/me`(팀명)
- `GET/POST/PATCH/DELETE /api/work-items`, `PATCH /api/work-items/{id}/status`
- `GET /api/days/{date}` (그날 근무 형태 + 표시할 항목 + 기존 입력), `PUT /api/days/{date}` (체크인 저장, 서버에서 MD 계산)
- `PUT /api/days/{date}/type` (연차·반차 등록), `GET /api/days?from=&to=` (요일 칩용 요약)
- `GET /api/reports/weekly?monday=YYYY-MM-DD` (구조화된 데이터 + 복사용 텍스트)
- `GET /api/reports/effort?tag=|itemId=&from=YYYY-MM&to=YYYY-MM`, `GET /api/reports/monthly?month=YYYY-MM`

**MD 계산·주간 보고 판정·월별 집계는 모두 서버에서** 하고 단위 테스트로 검증한다(포트폴리오 핵심 로직).

## 8.5 세부 규칙 (설계자 결정 — 검토에서 나온 질문 정리)

- **완료 → 진행 중 되돌리기**: `completed_at`을 비운다. 상태 이력 테이블은 두지 않는다(과거 주 보고가 바뀔 수 있음을 감수, 되돌리기는 드문 경우).
- **시작일**: 대기 항목에 처음 비중 > 0이 저장되면 `started_at` = 그 **기록 날짜**. 이후 더 이른 날짜에 기록이 생기면 더 이른 날짜로 당긴다.
- **완료일 이후 기록**: 허용하되 일일 화면에서 "완료된 항목" 표시. 시작·완료일 수동 수정으로 기록이 범위 밖에 놓여도 막지 않고 기록은 유지(경고만).
- **기록 없는 평일**(day_logs 없음): "기록 없음"으로 본다. 서버가 채워 넣지 않는다. 월간 근무일 수 = 해당 월에 MD > 0 기록이 있는 날 수.
- **태그 변경**: 집계는 항상 **현재 태그** 기준. 과거 기록 태그를 따로 저장하지 않는다.
- **기록이 있는 날을 연차/휴일로 바꿀 때**: 확인 창을 띄우고, 동의하면 그날 항목 기록을 삭제한다(하루 메모는 유지). 반차로 바꾸면 기존 비중을 유지한 채 0.5MD로 재계산.
