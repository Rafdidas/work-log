# Work Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 하루 0~3 비중 체크인으로 MD를 자동 분배·기록하고, 그 기록에서 주간 보고 초안과 기간별 투입 공수(MD)를 뽑아 복사할 수 있는 개인용 웹앱(팀 확장 대비)을 만든다.

**Architecture:** monorepo. `backend/`는 Spring Boot REST API(기능별 패키지: auth, item, day, report)로, MD 계산·주간 보고 판정·공수 집계를 모두 서버에서 하고 PostgreSQL(Flyway)에 저장한다. `frontend/`는 Vite+React SPA로 `/api`를 프록시해 같은 출처 httpOnly 쿠키 JWT로 인증한다. Docker Compose로 postgres+backend+frontend를 띄운다.

**Tech Stack:** Java 21, Spring Boot 3.5.x, Spring Data JPA, Spring Security, jjwt 0.12.x, PostgreSQL 16, Flyway, JUnit 5 + Testcontainers / Node 22, Vite, React 18 + TypeScript, Tailwind CSS v4(`@tailwindcss/vite`), `motion`(motion/react), TanStack Query v5, react-router v6, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-02-work-log-design.md` — 각 태스크 구현 전에 해당 절을 읽을 것.

## Global Constraints

- 단위는 MD만 쓴다. M/M 환산 없음. MD는 `numeric(4,2)` / `BigDecimal` scale 2, 표기 `"0.67MD"`, 시간 환산은 `MD × 8`을 소수 1자리로 표기(`"5.3h"`).
- 근무 MD: `WORK 1.00`, `HALF_AM 0.50`, `HALF_PM 0.50`, `ANNUAL 0.00`, `HOLIDAY 0.00`. 라벨: 근무 / 오전 반차 / 오후 반차 / 연차 / 휴일.
- 비중은 정수 0..3만 허용.
- 주 = 월~금. 보고 제목 `YYYY-MM-DD ~ YYYY-MM-DD {teamLabel}`, teamLabel 기본값 `개발1팀`.
- 날짜·"오늘"은 모두 `Asia/Seoul` 기준(`Clock` 빈 주입). 서버 기본 TZ에 의존 금지.
- 모든 데이터 조회는 로그인 사용자 `userId`로 범위 제한. 남의 리소스 id → 404.
- 팔레트: ink `#0C1821`, prussian `#1B2A41`(유일한 강조색), charcoal `#324A5F`, white `#FFFFFF`, canvas `#F4F6F8`, black `#000000`. 반투명(blur)은 상단 바/탭에만. 컬러풀한 상태색 금지(상태는 회색조 라벨).
- 폰트: Pretendard(CDN `cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9`) → 시스템 폰트 폴백.
- `prefers-reduced-motion` 존중.
- 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- 실행 전제: Docker Desktop 실행 중(Testcontainers·Compose), JDK 21, Node 22.

## Review Focus

1. **"오늘"이 UTC로 계산됨** — 컨테이너 TZ가 UTC면 오전 9시 전 KST 작업이 전날로 들어감. 기대: 항상 KST 날짜. → Task 3 `createInProgress_usesSeoulToday` 테스트.
2. **비중 전부 0 + 메모만 있는 날 저장** — 500이 아니라 MD 0으로 저장되고 메모 유지. → Task 4 `save_allZeroWeights_keepsMemos` 테스트.
3. **주 중간에 완료된 항목** — 그 주 해야 할 일에 있고, 달성한 일에 `(완료)`, 차주 업무엔 없음. → Task 5 `itemCompletedMidWeek` 테스트.
4. **월요일이 아닌 날짜로 주간 보고 요청**(URL 직접 입력) — 서버 400, 프론트는 `mondayOf()`로 정규화. → Task 5 `nonMonday_returns400`, Task 7 `mondayOf` 테스트.
5. **기록 없는 달·연도 경계** — 공수 조회에서 빈 달은 `0.00MD`로 나오고, 연도가 바뀌는 범위는 `2026-12`, `2027-01` 형식. → Task 6 `effort_fillsEmptyMonths_andYearBoundaryLabels` 테스트.

  - `final class MdAllocator { static Map<Long, BigDecimal> allocate(BigDecimal workMd, LinkedHashMap<Long, Integer> weights) }` — 결과 scale 2, 비중 0 → 0.00, 비중 합 0 → 전부 0.00. 합계가 정확히 `workMd`가 되도록 **최대 나머지 방식**: 각 항목 `floor(workMd*w/W, 2)` 후 남은 0.01 단위를 나머지가 큰 순(동률이면 입력 순서 먼저)으로 배분.
  - `GET /api/days/{date}` → `DayView {date, dayType, dayTypeLabel, workMd, memo, entries:[{itemId, title, tag, status, recurring, weight, md, memo, completedBefore:boolean}], waitingItems:[{itemId, title, tag}]}`
    - `entries`에 나오는 항목: IN_PROGRESS 항목 전부 + 그날 기록이 있는 항목(상태 무관) + `completedAt >= date`인 DONE 항목. 기록 없는 항목은 weight 0. `completedBefore = completedAt != null && completedAt < date`. 정렬 sort_order.
    - `waitingItems`: WAITING이고 그날 기록 없는 항목.
  - `PUT /api/days/{date} {memo, entries:[{itemId, weight, memo}]}` → 저장 후 `DayView` 반환.
    - weight 범위 밖 400. 잠긴 날(연차·휴일)에 weight>0 → 409 `DAY_LOCKED`.
    - day_log 없으면 `WORK`로 생성. md는 `MdAllocator`로 계산해 저장. weight 0이고 memo 빈 항목은 행 삭제. weight>0인 항목마다 `markStartedOn(item, date)`.
  - `PUT /api/days/{date}/type {dayType, confirm=false}` → 잠김 타입으로 바뀌는데 기록이 있고 `confirm=false`면 409 `ENTRIES_EXIST`; `confirm=true`면 entries 삭제(하루 memo 유지). 반차로 바뀌면 기존 weight로 md 재계산.
  - `GET /api/days?from=&to=` → `[{date, dayType, totalMd, hasEntries}]` (day_log 있는 날만)
  - `GET /api/days/leaves?from=&to=` → dayType != WORK 인 날 목록.
